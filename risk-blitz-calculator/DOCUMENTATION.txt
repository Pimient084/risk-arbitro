1. ¿CÓMO FUNCIONA LA APLICACIÓN Y CÓMO IMPACTA AL JUEGO DE MESA?
================================================================================

1.1 Propósito General
La aplicación RISK Blitz Calculator es una herramienta de análisis numérico 
diseñada para asistir a jugadores y árbitros en el juego de mesa RISK: Global 
Domination. Su función es determinar la probabilidad de victoria en combates 
tipo "Blitz" (resolución rápida de batallas) basándose en la razón de fuerzas 
A/D (Ataque/Defensa).

1.2 Impacto en el Juego de Mesa
En RISK estándar, los combates se resuelven mediante tiradas de dados con reglas 
probabilísticas determinadas. El Blitz es una variante donde la batalla se 
resuelve aplicando una regla simplificada basada en la proporción de tropas:

  • ZONA DE RIESGO (<25% prob. de victoria): El atacante no debe hacer Blitz.
    Se recomienda diplomacia o acumulación de fuerzas.
    
  • ZONA GRIS (25-75% prob. de victoria): La batalla es incierta. Los jugadores 
    pueden elegir hacer Blitz o negociar según su estrategia.
    
  • ZONA FAVORABLE (>75% prob. de victoria): El atacante tiene ventaja. Es 
    recomendable hacer Blitz para resolver rápidamente.

1.3 Impacto Específico
- Acelera el juego: Evita tiradas largas y tediosas en combates.
- Toma de decisiones informada: Los jugadores pueden evaluar riesgo/beneficio.
- Diplomacia mejorada: Transforma el conflicto en negociación cuando es incierto.
- Equidad: Basado en datos empíricos del juego, no en intuición.

2. TÉCNICA NUMÉRICA SELECCIONADA
================================================================================

2.1 Técnica: BÚSQUEDA DE RAÍCES (Root Finding)
Se seleccionó la búsqueda de raíces porque el problema puede formularse como:

    Encontrar los valores de razón A/D (x) donde P(x) = k
    
    siendo k ∈ {0.25, 0.50, 0.75} (puntos críticos de probabilidad)

Este es un problema clásico de búsqueda de raíces, ya que necesitamos resolver:

    f(x) = P(x) - k = 0

donde:
  • P(x) es la función de probabilidad interpolada
  • k es la probabilidad objetivo
  • f(x) es la función cuya raíz buscamos

2.2 Por Qué Búsqueda de Raíces y No Otras Técnicas

  ❌ Ajuste de Curva (Curve Fitting)
     - No es aplicable: Necesitamos encontrar puntos específicos, no 
       modelar toda la curva.
       
  ❌ Integración Numérica
     - No es necesaria: No necesitamos área bajo la curva ni 
       acumulación de probabilidades.
       
  ❌ Derivación Numérica
     - No es requerida: No buscamos puntos de máximo/mínimo ni 
       tasas de cambio.
       
  ✅ Búsqueda de Raíces (SELECCIONADA)
     - Exacta: Encuentra donde P(x) = k con precisión controlada.
     - Eficiente: Converge en 10-15 iteraciones.
     - Robusta: Garantizado hallar raíz si existe en el intervalo.

3. MÉTODO NUMÉRICO USADO: MÉTODO DE BISECCIÓN
================================================================================

3.1 Descripción del Método
El método de bisección es un algoritmo de búsqueda de raíces que funciona 
dividiendo repetidamente un intervalo por la mitad:

    Algoritmo:
    ─────────
    1. Começar con intervalo [a, b] donde f(a)·f(b) < 0 (hay raíz)
    2. Calcular punto medio: c = (a + b) / 2
    3. Evaluar f(c)
    4. Si |f(c)| < ε (tolerancia), terminar (raíz encontrada)
    5. Si f(a)·f(c) < 0, raíz en [a, c] → b = c
       Sino, raíz en [c, b] → a = c
    6. Repetir hasta convergencia

3.2 Propiedades del Método de Bisección

  Ventajas:
  • ROBUSTO: Siempre converge si la raíz existe en [a, b]
  • SIMPLE: Fácil de implementar y entender
  • PREDECIBLE: Número de iteraciones = log₂(b - a / ε)
  
  Desventajas:
  • LENTO: Converge linealmente (vs. convergencia cuadrática de Newton)
  • REQUIERE CAMBIO DE SIGNO: Necesita f(a)·f(b) < 0

  Para esta aplicación:
  • Converge en ~10-15 iteraciones (velocidad aceptable)
  • Tolerancia fijada en ε = 1e-6 (precisión de 0.0001%)
  • Máximo 100 iteraciones (seguridad)

3.3 Convergencia Garantizada
Para nuestro caso:
  • a = 0.2 (razón mínima)
  • b = 10.0 (razón máxima)
  • P(0.2) = 0.01 y P(10.0) = 0.999
  
Para cualquier k ∈ [0.25, 0.75]:
  • P(a) < k < P(b) → siempre hay raíz
  • Número de iteraciones ≈ log₂(10 - 0.2 / 1e-6) ≈ 24
  • En la práctica: ~10-15 por linearidad local

4. ALIMENTACIÓN DEL MÉTODO NUMÉRICO
================================================================================

4.1 Datos de Entrada
El método se alimenta de dos fuentes principales:

  A. DATASET EMPÍRICO (250 puntos)
  ────────────────────────────────
  - Rango: razones A/D de 0.2 a 10.0
  - 250 puntos espaciados uniformemente
  - Interpolación lineal entre cada par de puntos
  - Origen: Análisis empírico del juego RISK: Global Domination
  
  Ejemplo de puntos base (21 originales):
  ┌──────┬─────────────┐
  │ Ratio│ Probability │
  ├──────┼─────────────┤
  │ 0.2  │ 0.01        │
  │ 1.0  │ 0.38        │
  │ 2.0  │ 0.78        │
  │ 10.0 │ 0.999       │
  └──────┴─────────────┘
  
  Los 229 puntos restantes se generan por interpolación lineal uniforme:
  - Se crean 250 razones uniformes en [0.2, 10.0]
  - Para cada razón, se interpola la probabilidad usando los 21 puntos base
  
  B. FUNCIÓN DE INTERPOLACIÓN
  ────────────────────────────
  Para cualquier razón x en [x₁, x₂]:
  
      P(x) = P(x₁) + (x - x₁) · (P(x₂) - P(x₁)) / (x₂ - x₁)
      
  Esta función aproxima la verdadera curva P(x) de forma lineal a trozos.

4.2 Parámetros de Bisección
  • Tolerancia (ε):           1e-6 (convergencia)
  • Máximo de iteraciones:    100 (seguridad)
  • Probabilidades objetivo:  0.25, 0.50, 0.75
  • Intervalo de búsqueda:    [0.2, 10.0] (rango de razones A/D)

6.2 Método Clave: bisection(targetP)

  Código:
  ───────
  bisection(targetP) {
      let a = this.empiricalData[0].ratio;
      let b = this.empiricalData[this.empiricalData.length - 1].ratio;
      let iterations = 0;

      let fa = this.predictProbability(a) - targetP;
      let fb = this.predictProbability(b) - targetP;

      // Verificar que existe raíz
      if (fa * fb > 0) return null;

      // Iteraciones de bisección
      let c, fc;
      while (Math.abs(b - a) > this.tolerance && 
             iterations < this.maxIterations) {
          
          c = (a + b) / 2;
          fc = this.predictProbability(c) - targetP;
          iterations++;

          if (Math.abs(fc) < 1e-10) break;

          if (fa * fc < 0) {
              b = c;
              fb = fc;
          } else {
              a = c;
              fa = fc;
          }
      }

      return {
          ratio: (a + b) / 2,
          probability: this.predictProbability((a + b) / 2),
          iterations: iterations,
          error: Math.abs(finalProb - targetP)
      };
  }

6.3 Inicialización

Al construir BisectionModel, automáticamente:

  1. Carga los 250 puntos empiricalData
  2. Calcula los 3 puntos críticos llamando findCriticalPoints()
  3. Ejecuta bisection(0.25), bisection(0.50), bisection(0.75)
  4. Almacena resultados en criticalPoints
  5. Registra en consola: "✓ Puntos críticos encontrados por Bisección"

  Ejemplo de consola:
  ──────────────────
  ✓ Puntos críticos encontrados por Bisección:
    P=25%: {ratio: 0.634, probability: 0.250, iterations: 11, error: 0.00001}
    P=50%: {ratio: 1.191, probability: 0.500, iterations: 12, error: 0.00001}
    P=75%: {ratio: 2.045, probability: 0.749, iterations: 11, error: 0.00012}

6.4 Métodos de Apoyo

  A. linearInterpolate(x, x1, y1, x2, y2)
     └─ Interpola linealmente entre dos puntos
  
  B. predictProbability(ratio)
     └─ Retorna P(ratio) usando interpolación entre los 250 puntos
     └─ Usada por bisection() en cada iteración
  
  C. getRecommendation(probability)
     └─ Convierte probabilidad en color y estrategia:
        P > 0.75 → 🟢 USAR BLITZ
        P < 0.25 → 🔴 EVITAR BLITZ
        Else     → 🟡 ZONA GRIS
  
  D. getData()
     └─ Retorna {empirical, criticalPoints, tolerance}
     └─ Usada por la UI para gráficos

6.5 Integración en la Aplicación

  Archivo: app.js
  ────────────────
  // Inicialización
  let blitzModel = new BisectionModel();
  
  // En setupBlitzSection()
  function setupBlitzSection() {
      const btnCalculate = document.getElementById('btnCalculateBlitz');
      
      btnCalculate.addEventListener('click', () => {
          const attackTroops = parseFloat(inputAttack.value);
          const defenseTroops = parseFloat(inputDefense.value);
          
          // Calcular razón A/D
          const ratio = attackTroops / defenseTroops;
          
          // Obtener probabilidad (interpolada)
          const probability = blitzModel.predictProbability(ratio);
          
          // Obtener recomendación
          const recommendation = blitzModel.getRecommendation(probability);
          
          // Mostrar en UI
          displayResult(ratio, probability, recommendation);
      });
  }

6.6 Complejidad Computacional

  Cada cálculo de probabilidad: O(n) = O(250)
  ├─ Búsqueda de intervalo: máx. 250 comparaciones
  └─ Interpolación: O(1)

  Cada llamada a bisection(): O(log ε) ≈ O(20)
  ├─ 10-15 iteraciones típicamente
  ├─ Cada iteración: O(250) [evalúa predictProbability]
  └─ Total por punto crítico: ~O(20 × 250) = O(5000)

  Inicialización total: O(3 × 5000) = O(15000) operaciones
  └─ Negligible (< 1ms en navegadores modernos)

  Cálculo en tiempo de ejecución: O(250)
  └─ Respuesta instantánea (< 5ms)
